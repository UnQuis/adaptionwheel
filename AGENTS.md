# AGENTS.md

## What this repo is

- **Not a source repo for the Terraria mod.** The `3670588280/` folder mirrors the Steam Workshop item **ADAPTIONWHEEL** (Workshop ID `3670588280`): compiled `ADAPTIONWHEEL.tmod` builds under `3670588280/<tmodLoader-version>/`, plus `workshop.json` metadata. The C# source lives elsewhere.
- **Also the source repo for a Minecraft port**: a NeoForge 1.21.1 mod `adaptionwheel` (Adaption Wheel, Mahoraga from Jujutsu Kaisen) built from the decompiled Terraria mod for maximum fidelity. The Gradle project lives at the repo root.
- **It IS a git repo** (this line used to say otherwise): private `github.com/UnQuis/adaptionwheel`, default branch `main`. Other branches: `26.3` (newer Minecraft, usually checked out in a worktree) and `arena/*`. Pull before working.

## Layout

### Terraria artifacts (`3670588280/`)
- `3670588280/<tmodLoader-version>/ADAPTIONWHEEL.tmod` — compiled mod builds.
- Subdirectory names (`2025.12`, `2026.1`, `2026.2`) are **tModLoader versions**, not mod versions (match the `TMOD.*` header inside each `.tmod`).
- `workshop.json` — Steam Workshop metadata. Edit only when republishing.
- `3670588280/test/` — stale scratch Gradle project holding an **outdated copy** of the mod resources (missing newer assets). Ignore it; never edit it expecting changes to ship.

The distinction is load-bearing: a material listed under two tiers stays reachable from the lower one and trainable at the higher one, which is the only reason the Diamond tier can be raised at all (the whole deepslate family is stone-band, so `tierOf` calls all of it Stone). **The Diamond tier trains on the entire deepslate family** — deepslate and all its cut variants, infested deepslate, tuff, calcite, dripstone — because its original list (obsidian, ancient debris, netherite blocks, respawn anchors, lodestone) was ungrindable: ancient debris barely spawns. It also keeps `#minecraft:diamond_ores` and `#minecraft:emerald_ores`, which vanilla bands as *iron*-pickaxe blocks, so they train whichever tier you are on. **Luck:** each tier multiplies what ore drops and the experience it pays by 1/2/3/5/10 by tier (`FistTiers.luckMultiplier`, stated on the HUD row as `LUCK xN`). Implemented in `server/FistLuck.java` on `BlockDropsEvent`, which fires from `Block.playerDestroy -> Block.dropResources -> CommonHooks.handleBlockDrops` after the loot table has run but before anything enters the world, and carries the items and the XP in one object — so fortune and silk touch are already baked in before the multiplier applies, and drops and XP cannot drift apart. Stacks are merged up to their limit rather than spawning N entities. Scope is the `adaptionwheel:fist_luck` block tag, which ships as the eight vanilla `*_ores` tags plus `nether_quartz_ore` (there is **no** `minecraft:ores` tag in 1.21.1, and nether quartz ore has no tag of its own); stone, wood and wool are deliberately untouched so stone farming stays where vanilla left it. Config `mutations.fistMastery.luckEnabled`. Luck stays live during Adversity, unlike levelling — it is a property of how strong the fist currently is, in the same family as the harvest gate and the speed. Every unlock and tier-up prints which material trains it (`adaptionwheel.fist.material.*`) and how many blocks the next level costs. **Hook: `PlayerEvent.HarvestCheck` only — no mixin**, because that one check gates both the drops and the destroy-speed divisor. **Speed is tool parity, not a bonus**, and the prototype is chosen **per block** across the four vanilla tool classes (pickaxe/axe/shovel/hoe): soil and sand copy the shovel, logs the axe, foliage the hoe, stone and ore the pickaxe. All four classes of a tier declare the same number (wood 2, stone 4, iron 6, diamond 8, netherite 9 in 1.21.1), but asking the tool that can actually mine the block is what makes that true by construction. **Read the speed from the tool's own `Tool.Rule` list, never off a block and never off `defaultMiningSpeed`** — both of those read 1.0 and silently reduce the fist to bare-hand speed: `defaultMiningSpeed` is only the fallback for uncovered blocks, and `Item.getDestroySpeed(stack, block)` returns >1.0 only when a rule covers *that* block, so a diamond pickaxe reports 1.0 on dirt (1.21.1 keeps dirt in shovel-only `mineable/shovel`, out of `mineable/pickaxe` entirely) — which is exactly how a diamond fist ended up taking 15 ticks on soil where a diamond shovel takes 2. Tools are looked up by id through `BuiltInRegistries.ITEM` (the decompiled `Items` class is missing `copper_pickaxe` here); declared speeds are cached per (tier, class), and a missing tool makes the tier inherit the speed below. It is applied as a **multiplier** on the incoming `BreakSpeed` value, not an absolute overwrite: vanilla's pipeline is `1.0 × BLOCK_BREAK_SPEED × haste ÷ 5 airborne × submerged`, and multiplying swaps the 1.0 while keeping every modifier, whereas assigning an absolute value would ignore haste and remove the airborne penalty. **The client must answer too** — `MultiPlayerGameMode.continueDestroyBlock` accumulates break progress client-side and destroys the block itself, so a server-only hook makes the player mine at 1/3.3 of the intended speed. `FistMastery.onHarvestCheck` therefore runs on both sides (via `SurfaceAdaptations`), and the tier-reach rule lives in `FistTiers.reachTier` with **one** implementation called by both `FistMastery` and `ClientAdaption` — they previously drifted, leaving the client mining at wooden speed for a whole tier after the server had unlocked stone. **Harvest bands follow vanilla's own tool tiers**, sourced from the `needs_*_tool` block tags (cumulative reach): Wood = blocks needing no pickaxe; Stone `= #minecraft:needs_stone_tool` (+ coal, which vanilla leaves untiered); Iron `= needs_iron_tool`; Diamond `= needs_diamond_tool`. **There is no copper tier.** Vanilla's ladder has six materials, but copper owns no tool band — a copper pickaxe is a stone-band tool — and `copper_pickaxe` is absent from this registry entirely, so a literal six-tier ladder had a rung that granted nothing and cost a whole eight-level climb. It is folded into **Iron**, which now trains on the union of the Nether band (netherrack/basalt/blackstone/glowstone/magma/soul soil/crimson family — the only unclaimed material band) and everything `needs_iron_tool`. Saving progress: `WheelData.migrateLegacyConcepts` folds a carried `Fist_Copper` level into `Fist_Iron` on load, clamped to the cap, so a wheel played on the old layout keeps its investment. Netherite is what *no* pickaxe can harvest (dragon egg, spawner, reinforced deepslate); its level 8 is Instabreak. Material classes are data-driven block tags `data/adaptionwheel/tags/block/fist_{wood,stone,iron,diamond,netherite}.json`; a block in no tag is always harvestable (vanilla already allows it). Every unlock and tier-up prints which material trains it (`adaptionwheel.fist.material.*`) and how many blocks the next level costs. Config `mutations.fistMastery.fistSpeedScale` (default 1.0) multiplies the tool speed. **Instabreak** = Netherite 8: any breakable block in one tick, toggled with a keybind (default G, `client/AdaptionKeybinds.TOGGLE_INSTABREAK_KEY`) and validated server-side (`network/FistInstabreakPayload`); blocks with destroy speed -1 (bedrock, end portal) stay unbreakable.   - `server/AdaptionCommand.java` — `/adaptionwheel status|list|info|grant|ungrant|analyze|reset|registry` (reads self-serve, mutations require perm 2); surgical grants go through `AdaptionEvents.debugGrant/debugUngrant/debugReset` (no heal/voice/events). **The concept argument is `StringArgumentType.string()`, and it MUST NOT be a custom `ArgumentType`.** `word()` does not reject a colon, it *stops reading at one*, so `Existence_draconicevolution:draconic_guardian` silently became `Existence_draconicevolution` and `Contact_minecraft:zombie` became `Contact_minecraft`: the command reported a successful grant, nothing happened, and there was no error to find. That silently killed every namespaced concept, i.e. the whole `Contact_*`/`Offense_NPC_*`/`Drop_NPC_*` family and every modded boss. A custom argument type parses correctly and then **prevents players from logging in at all**: the command tree is mirrored to the client, which rebuilds each node from a serializer looked up by class in `ArgumentTypeInfos`' private static map, filled from a hardcoded bootstrap list with no NeoForge registration hook — so the client throws `Unrecognized argument type` and drops the connection with `Invalid player data`. `string()` carries a colon when the value is quoted (`grant "Contact_minecraft:zombie"`; `grant Type_Fire` needs no quotes) and stops at whitespace so a trailing `<target>` still parses. `truncationHint` turns a forgotten quote into an explicit error by spotting a key that ends in a known mod namespace — the fingerprint of a string cut at its colon. `test/CommandTreeSyncTests` walks the real registered tree and asserts every argument type in it is client-serializable (the same predicate the packet builder throws on), which is the only check that catches a login-breaking argument type: a dedicated-server boot is server-side and misses it. `grant <concept> <player>` exists as a **sibling** of the `level` node, not a child of it — nested under `level` it only ever matched `<concept> <level> <player>`, which already existed, so naming another player without inventing a level died with "Expected integer" pointing at the player's name. `grant` resolves the level per kind (max for leveled, ignored-with-a-message for one-time) and its upper bound tracks `PlayerAdaption.MAX_LEVEL` rather than a literal 8; `grant all [domain]` dumps a whole domain; `ungrant` removes a single adaptation (the only undo besides a full reset) and clears the fist's runtime state when the mutation is what went; an unknown concept replies with near-matches by substring instead of a dead end.

## Commands

- Build: `./gradlew build --no-daemon` (first run downloads Minecraft + runs neoForm; long). Runs/tests: `./gradlew runClient`, `./gradlew runServer`, `./gradlew runData`. No lint/test framework configured.

## Gotchas

- `.tmod` files are **not** plain ZIPs: `TMOD.<version>` header + .NET length-prefixed version + hash + signature + 4-byte length + file table + raw-DEFLATE blobs (`zlib.decompress(blob, -15)`). Extract with `/tmp/opencode/tmod_extract.py`; decompile with `ilspycmd` (`.NET` tool) — the decompiled reference source lives at the repo root in `ADAPTIONWHEEL/` (incl. original `Assets/Sounds/*.wav`, textures, shaders, localization).
- `.rawimg` Terraria textures = XNB TiledImage: int32 tile count, then per tile (int32 w, int32 h, raw BGRA pixels). Convert with Python/PIL.
- Surface physics: ice/slime/cobweb are handled by **mixins** (`mixin/` package) so vanilla physics apply unchanged on both sides; lava swimming is tick-based velocity conversion in `ClientSurfaceHandler` (+ server mirror `AdaptionEvents.applySurfaceEffects`) because NeoForge 21.1 has no fluid-movement hook. Don't replace the mixin approach with post-tick velocity multipliers — that halved walk speed (the original bug).
- **Important:** `gradle.properties` is read by Gradle as ISO-8859-1 — keep `mod_description` and any `${...}`-expanded values in `neoforge.mods.toml` ASCII-only or the text will be mojibake'd.
- **NeoForge 21+ dependency format:** `[[dependencies.<modid>]]` uses the `type` field (`required|optional|incompatible|discouraged`); the legacy Forge `mandatory=true/false` key is silently IGNORED and every parsed dependency defaults to REQUIRED. The DE soft-compat entry once crashed every install without Draconic Evolution because of this.
- NeoForge 21.1 API quirks hit during development: **`LivingIncomingDamageEvent` DOES exist** (this file used to claim the opposite) and it `implements ICancellableEvent`, fired from the very top of `LivingEntity.hurt()` via `CommonHooks.onEntityIncomingDamage` with `return false` on cancel. `LivingDamageEvent.Pre` fires later, inside `actuallyHurt()`. **Anything cancelled in the incoming handler can never be seen by the Pre handler** — reflection/compensation logic has to live in the incoming one (this is why the existence reflection used to be dead code). `DamageSource.type()` returns `DamageType` (use `typeHolder().getRegisteredName()` for the id); `AttributeModifier(ResourceLocation, double, Operation)` with `Operation.ADD_VALUE/ADD_MULTIPLIED_BASE`; `AttributeInstance.removeModifier(ResourceLocation)`; `MobEffectEvent.Applicable.Result.DO_NOT_APPLY`; `PlayerTickEvent` lives in `net.neoforged.neoforge.event.tick`; `StreamCodec.composite` supports at most 6 components (use `StreamCodec.of` for more); `Mob` has no `isBoss()` — boss detection lives in `BossHelper` (hardcoded Wither/EnderDragon/Warden + Chaos Guardian + boss tag); loot params in 1.21.1 use `ATTACKING_ENTITY`/`DIRECT_ATTACKING_ENTITY`/`LAST_DAMAGE_PLAYER` (renamed from `KILLER_ENTITY`/`DIRECT_KILLER_ENTITY`/`LOOTING_ENTITY`); `LootParams.Builder` takes a `ServerLevel`; `FoodData` has no `getMaxFoodLevel()` — max food is the constant 20.
- **The block-drop gate is `PlayerEvent.HarvestCheck`, NOT `Player.hasCorrectToolForDrops`.** NeoForge's patch swapped the latter for `BlockState.canHarvestBlock(...)` → `EventHooks.doPlayerHarvestCheck(...)`, which posts the overridable `HarvestCheck` event. The *same* check also picks the destroy-speed divisor (`/30` with a correct tool vs `/100` without) inside `BlockBehaviour.getDestroyProgress`, so a single `setCanHarvest(true)` grants both the drops and the correct-tool speed bonus — no mixin required. Confirm in `~/.gradle/.../neoforged/neoforge/<ver>/…-userdev.jar` → `patches/net/minecraft/server/level/ServerPlayerGameMode.java.patch`.
- **Curios**: `ICuriosItemHandler.isEquipped(Item)` is a default method delegating to `findFirstCurio(Item).isPresent()`. Therefore whenever `wearingWheel(player) == false`, `getWheelStack(player)` is **guaranteed empty** — writing to the wheel from a `!wearing` branch is a guaranteed no-op. Use `PlayerAdaption.equippedStack` (captured while worn) for those writes.
- **1.21.1 gametests**: templates live at `data/<ns>/structure/<path>.nbt` — **singular** `structure` (not `structures/`) and **gzipped binary NBT** (SNBT text is only read from the IDE test-structures dir). NeoForge prefixes the template with the lowercased test class name unless `@PrefixGameTestTemplate(false)` is set. Any test calling `GameTestHelper.makeMockServerPlayerInLevel()` is **broken while Curios is installed**: the mock login makes Curios throw `Payload curios:sync_data may not be sent to the client!`, failing the test before its body runs. `./gradlew runGameTestServer` is the headless runner (`forge.enabledGameTestNamespaces` is already wired in `build.gradle`).
- Mixin quirks hit with the DE laser mixin: an `@Redirect` handler parameter must match the **exact** receiver type in the target bytecode (`Player`, not `LivingEntity` — supertypes are rejected at apply time with `InvalidInjectionException`); `@At(target = "setHealth(F)V")` without an owner matches any receiver, which keeps the injection resilient; optional mixins into another mod's classes must be gated through an `IMixinConfigPlugin` (`shouldApplyMixin` → `FMLLoader.getLoadingModList().getModFileById(...)`) or Mixin logs errors for the missing target class.
- Draconic Evolution facts (from the jar at the repo root): the Chaos Guardian (`draconicevolution:draconic_guardian`) is NOT in any boss tag — recognition is hardcoded via string id; its parts are NeoForge `PartEntity`s, so generic part unwrapping covers them; ALL guardian damage types bypass armor/resistance/effects/shields/cooldowns and most are tagged `is_explosion`/`is_projectile` (so vanilla-tag categories already partially apply); the charged twin laser writes health directly (handled by mixin). DE needs CodeChickenLib + BrandonsCore at runtime for dev-server testing (fetchable from Modrinth).
